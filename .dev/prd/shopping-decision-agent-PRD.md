## 1. 背景与目标

用户在购物时面临"信息过载"和"决策疲劳"：面对海量商品和复杂参数，难以判断哪件商品最适合自己的使用场景。本项目打造一个个人购物决策 Agent，从"用户提出购买需求"到"系统完成检索、对比、推荐、下单"，提供端到端决策支持。

**核心价值**：用户只需说明想买什么，Agent 负责检索、分析参数、对比口碑、给出明确建议，并在用户确认后代为下单（到支付确认界面为止）。

## 2. 功能范围

### 2.1 包含的功能（In Scope）

- [ ] 需求输入：用户用自然语言描述购买需求（商品类型 + 使用场景 + 预算约束）
- [ ] 商品检索：在京东/天猫等平台自动检索候选商品
- [ ] 商品信息采集：读取商品详情页的关键参数、价格、评价、品牌影响力/口碑
- [ ] 智能对比分析：基于用户场景综合参数、价格、评价、品牌口碑，推荐最优购买选择
- [ ] 建议理由：给出明确推荐结论与可解释的理由
- [ ] 代下单：用户确认推荐后自动加入购物车并跳转支付界面，仅保留支付确认环节
- [ ] 交互形态：第一版为 CLI + Agent 对话式工作流，本地运行；后端模块保持 API 可扩展性（不拆前后端）

### 2.2 不包含的功能（Out of Scope）

- 支付密码/指纹代付（必须用户本人确认）
- 多用户账号体系（单用户个人 Agent）
- 比价历史趋势分析（后续迭代）
- 移动端 App（先 Web/CLI，验证后再移植）

## 3. 用户故事

```
作为一名 个人购物用户
我想要 用自然语言发起购物需求后，由 Agent 检索并对比商品
以便 摆脱参数比对和决策疲劳，获得明确、可信的购买建议
```

```
作为一名 个人购物用户
我想要 在确认建议后代为下单，仅需确认支付
以便 减少操作步骤，同时保留最终支付控制权
```

## 4. 验收标准

### 4.1 功能验收

1. GIVEN 用户输入"我要买人体工学椅，预算1000元，日常在家办公使用"
   WHEN 系统完成检索与对比
   THEN 输出 2-3 个推荐商品，每个包含参数、价格、评价、品牌口碑与推荐理由
2. GIVEN 用户输入非具体品类需求（如"相亲伴手礼"）
   WHEN 系统完成检索与对比
   THEN 能基于场景理解给出候选商品建议并说明推荐逻辑
3. GIVEN 用户确认某个推荐商品
   WHEN 系统执行下单流程
   THEN 商品加入购物车并跳转到支付确认页，不自动完成支付
4. GIVEN 任一推荐商品
   WHEN 展示推荐理由
   THEN 理由必须引用该商品的具体参数/价格/评价/品牌信息，而非泛泛而谈

### 4.2 边界与异常

1. 检索不到商品或平台反爬拦截：明确提示用户，不静默失败
2. 商品详情参数缺失：标注"未获取"，推荐逻辑不得捏造参数
3. 预算硬约束：超预算商品直接淘汰，并在结果中说明
4. 下单失败（缺货、价格变动）：提示用户并给出备选方案
5. 用户中途取消：随时可停止流程，不产生任何订单

## 5. 非功能需求

- 性能：从需求输入到推荐输出，目标 3 分钟内完成
- 准确性：商品参数、价格必须来自真实详情页，禁止 LLM 编造
- 安全：Cookie/登录态仅用于本地下单，不泄露；支付必须人工确认
- 兼容性：本地运行（macOS），后续可 Web 化
- 可维护性：搜索、分析、下单模块解耦，便于替换平台适配；后端服务层预留 API 接口，Web 化时无需重写核心逻辑

## 6. 交互流程

```
用户操作 -> 系统响应
1. 用户输入购买需求（商品 + 场景 + 预算） -> 解析意图，生成搜索关键词与关键参数
2. 系统检索京东/天猫 -> 获取候选商品列表
3. 系统读取候选商品详情 -> 采集参数、价格、评价、品牌口碑
4. 系统对比分析 -> 输出推荐商品 + 推荐理由
5. 用户确认推荐 -> 自动加购并跳转支付页
6. 用户确认支付 -> 完成购买（支付环节由用户操作）
```

## 7. 依赖与前置条件

- 依赖其他功能/模块: 无（全新项目）
- 外部依赖:
  - 京东/天猫登录态（Cookie，用于检索与下单）
  - Qwen LLM（需求解析、场景理解、对比推荐）
  - Python Playwright（浏览器自动化）
  - SQLite（本地历史记录，可选）
